# FREEZE_MPGD26_2026-08-12 — the frozen analysis and the full-June condor campaign

**The micro-TPC waveform-first reconstruction is frozen for MPGD26 at the
commit recorded in `condor_campaign/FREEZE_COMMIT.txt` (built by
`condor/make_reco_package.py`, which refuses a dirty tree). The full June
cosmic dataset — 214 (subrun, detector) rows across 144 subruns — is
enumerated, classified against the frozen calibrations, and packaged for
lxplus condor. This file is the campaign runbook.**

Development continues after the conference; the open items are in §8. Nothing
in this campaign changes reconstruction behaviour — it is the frozen chain at
scale, plus one *gated* config decision (the t0 prior, §4).

## 2 · ⚠️ Discovery made while freezing: production runs the `delay` kernel branch

`wft/model.py` selects the sharing-kernel form from the bundle's `share_mode`
field. **Every production bundle carries `share_mode: null`** → the loader
falls back to `'delay'` (delayed smeared-template copies), not the `'lp'`
cascaded-one-pole branch the "share_lp" name suggests. The `share_lp: 1.0`
entry in `hyper` is inert — nothing reads it. Nothing in the analysis tree
calls `set_share_mode`, so **the bench harness scored the same branch**:
every number since the 8-06 merge — the fleet digest, the t0-prior A/B, the
kernel arms' "shipped behaviour" reference, the multi-track bit-identity — is
the delay branch with the lp-fitted hypers. The system is *self-consistent*;
only the naming ("share_lp kernel") is misleading.

Measured (sat_det3, 250 events, lp2_t0p, stamp `share_mode='lp'` vs as-is):
median |Δp0| 10–20 µm, 5–8 % of events hop > 0.5 mm (candidate/basin flips),
lp chi2 ~4 % lower, quality_ok +0.4/+4.0 pp (x/y). Neither branch is
"validated better" — the *delay-as-loaded* behaviour is what every gate
measured, so **the freeze keeps it**. Stamping `'lp'` (or deciding between the
branches properly) is a post-MPGD26 item together with the Y kernel shape
(F6/F12); it would re-open every gate.

## 4 · The t0-prior gate (decided policy: calibrate + gate)

The σ=5 trigger prior is validated **on det3 only**. For det2/4/6/7:

1. ftst-carrying bench caches rebuilt (`bench_cache_ftst.pkl`, 8-12 — the
   7-30 caches lack per-plane `ftst`).
2. `08_t0_abs_calib.py <key> --bundle .../calib_bundle_lp` per detector →
   `wft/t0_prior/t0_abs.json`. (det2's ftst ladder is visibly noisier than
   det3's clean −10 ns/step — expect the gate to actually decide something.)
3. Gate bundles `calib_bundle_lp_t0p` = copy of `calib_bundle_lp` +
   `t0_abs` + `t0_prior_sigma: 5.0` (same construction as det3's, T0_PRIOR §8).
4. **Phase-1 condor jobs** run each golden key twice: `prod` (frozen bundle,
   = the 7-31 configuration re-run on frozen HEAD) and `t0p`. Full statistics,
   production code path.
5. `condor/gate_eval.py <key>` scores both arms through the standard
   01→02→03 accounting (backup-swaps the live parquet, restores even on
   error) and prints the verdict. **Rule: ADOPT iff no regression beyond
   (within5 −0.1, far +0.1, core +2 %) and ≥1 improvement.** det3 is not
   gated (already validated). ~~its prod arm doubles as the non-regression
   check against `FLEET_DIGEST.md`~~ — **struck 8-12, both premises false;
   see §7**: the digest predates the current code generation and det3's
   manifest bundle already carries the prior. There is no valid external
   reference for the campaign; its internal A/Bs and the regenerated digest
   are the record.
6. Adopted detectors get `--t0p-dets mx17_X,…` at the phase-2 package build;
   fallback detectors run `calib_bundle_lp` everywhere. Mixed fleet config is
   acceptable and is recorded per row in `job_row.json`.

## 6 · Rules that bind the campaign

- **Never merge or compare results across bundles** without saying so — a
  fit is labelled by its bundle (`job_row.json.bundle_used`); off-conditions
  rows carry `off_conditions: true` and are quoted as trends only.
- **Promotion is explicit** (`collect_results.py --promote`), prod rows only,
  never gate arms; anything replaced is parked in `wft/pre_campaign_backup/`.
- Status comes from the JSON summaries, not from prose in logs
  ([[analysis-status-from-summaries-not-logs]]). ~~validate det3 against the
  known digest row~~ — struck 8-12 (§7): `FLEET_DIGEST.md` is a historical
  artefact of the pre-freeze code and is not a validation reference. Sanity
  checks are internal: arm-vs-arm, and campaign-digest implied-v flatness.
- The t0p arms must NOT be produced with CLI flags — the prior lives in the
  bundle, and `t0_prior_for` activates it from bundle fields alone (verified
  in the 8-12 smoke).

### ⚠ The §4/§6 non-regression check against `FLEET_DIGEST.md` does not work

Both halves of it fail, so no campaign result should be checked against that
file. Measured 2026-08-12 while running the gate:

1. **det3's arm and the digest row are different bundles.** The live parquet
   the digest was built from carries `calib_bundle_lp2`, `t0_prior_sigma:
   None`, `t0_abs: {}` — no prior — while the campaign's det3 prod arm is
   `calib_bundle_lp2_t0p`. The comparison measures the prior, not a regression
   (campaign 93.276 / 4.015 / 0.447 vs digest 93.5 / 3.7 / 0.46).
2. **The frozen code does not reproduce the 7-31 recos even at identical
   bundle.** det2 prod vs the live 7-31 parquet — same `calib_bundle_lp`, same
   3666 events, same `event_id`s — differs in 39 of 45 shared columns: median
   |Δp0| 0.161 mm (21 % of events move > 0.5 mm), median |Δθ| 0.46°, median
   |Δt0| 41 ns, `x_quality_ok` 0.990 → 0.603. `wft/` has had the RC-ladder
   kernel + per-plane angle constants (`9dd7d6e`), the t0 prior (`f9e18d2`) and
   multi-track (`39db695`) since, so this is expected code evolution — but it
   means FLEET_DIGEST is an artefact of older code and is not a reference.

Aggregate impact is small (det2 prod within5 91.687 vs 91.9, far 4.591 vs 4.4)
**except σθX, 1.14 → 1.30 (+14 %)** — check that before any slide quotes
angles. `quality_ok` does not gate the headline accounting (`compat.load_table`
applies it only under `quality_only=True`), so the collapse does not touch
within5/core. Gate A/Bs are unaffected: both arms come from the same frozen
code. The digest must be **regenerated from campaign outputs** (§5 step 5),
not compared against.

Provenance gap: the bundles record `code_commit: 1292d91`, which is not a valid
object in this repo, so the 7-31 behaviour cannot be bisected as things stand.
(This matches the recorded trap in [[wft-t0-prior-gate]]: the validated
R&D-line config "is NOT in shipped code; events.parquet (commit 1292d91) is
not reproducible by it" — known since 8-11, under-weighted when §4 was
written.)

**σθX resolved to a population/mapping effect, not degraded fits (8-12).**
On det2 events `slope_reliable` in BOTH generations, median |Δw| is
0.0002–0.0004 (≈ 0.01–0.02°) — the per-event slopes are unchanged. What moved:
`slope_reliable` 0.663 → 0.620 (x) / 0.610 → 0.535 (y), i.e. the σθ
*population* changed, and `9dd7d6e`'s per-plane angle constants changed the
w→angle map. The trustworthy judge (implied-v flatness, WFT §35) improves
dramatically under the frozen code (det3 vsp 2.12/3.40 → 0.78/1.15). Slides
must quote angle numbers ONLY from the regenerated campaign digest — the old
σθ 1.08/1.11 det3 figures in `mpgd26/slides/NOTES.md` are pre-freeze vintage.

### Tier B (det3 drift scan): DEFERRED from the conference path (8-12)

All 7 `--vrefit` jobs fail by design gap: `wft.calibrate` needs hits-chain
reference products (`cache/event_results_veto50.pkl` +
`alignment_tpc_veto50/alignment.json` from `03_alignment_and_tpc.py --veto=50`)

stages. Decision: **defer** — the drift-gap physics for the conference is
already covered by the 7-30 bench-line results (`GAP_STUDY_2026-07-30.md`,
`gap_vs_drift`), which remain valid; no slide needs a fresh wft reco of the
drift scan. To unblock post-conference: run `03_alignment_and_tpc.py <key>
--veto=50` locally for the six drift-scan subruns (row 100 also lacks the
event cache), then either run the v-refits locally or extend the job to ship
the alignment products.
