**How old paths still work:**
- A whole moved tree's old path is now a symlink to the new tree, with `<name>.MOVED.txt` beside it.
- The links resolve through **FUSE** (`/eos/...`), so local scripts and docs keep working unchanged.
- **They do not resolve through `root://eosuser.cern.ch`**, because the target is on the other instance. An
  xrdcp/xrdfs URL must use the new path on `root://eosexperiment.cern.ch`.
- Code, submit files, `docs/PARAMETERS.md` and the READMEs were repointed (`tools/eos_move/repoint.py`, 126 files).
  Result records (JSON, report text) keep their historical paths and resolve through the links.

**Caveats:**
- **FUSE staleness:** a directory created through FUSE and then filled through xrootd showed `?` entries on the same
  lxplus node for a long time. Server-side (`eos ls`, `xrdfs stat`) the files are correct. The tool therefore
  never reads the destination through FUSE. Two places still show it on that node: `analysis/user_misc/test` and
  `cosmic_bench/x17rerun/m3_audit/prod` (12 symlinks to the June M3 ray files, correct server-side).
- **EOS file versions** (`.sys.v#.*`, old versions of re-written files) were not carried over. A new copy starts its
  own version history.
- The user copies were removed with `eos rm -r`, so they sit in the user recycle bin until it expires. The quota had
  already dropped to 43 %.
