## C9 · The reconstruction's common mode moves with the signal — fix written (opt-in), validation pending

`wft.io` subtracts the plain per-sample median of each 64-channel block. On det7 (6-26, 495 V, FEU 08, 4000 events)
the track clusters are ~17 strips wide, and against a median that masks the cluster ±3 strips:

| strips of the block masked | baseline error at the pulse peak, median / p90 | largest error in the window, median |
|---|---|---|
| 1–8 | 0 / 3.5 ADC | 3.5 ADC |
| 8–20 | 2.5 / 15 ADC | 9–10 ADC |
| 20–40 | 4 / 51 ADC | 104 ADC |

Under 1 % of a ~4000 ADC peak, but applied to every strip of the block: 10–25 % of a neighbour's tail, which is what
the RC kernel's σ0 and D_rc, and the D_T stacks, are measured from. cloud_basics' stacks used a masked common mode;
the reconstruction never did. Fix: `wft.io.masked_block_median`, opt-in `WFT_CM_MASK=<half-width>` (default 0 =
bit-identical), reference-free two-pass median; on a toy (30-strip track in one block) the baseline error on the quiet
strips goes from −16 to −1.3 ADC. → W11: rebuild the golden calibration caches with it and gate it (resolution, χ²,
σ0, D_rc) before the freeze.

## C10 · Common mode, investigated (2026-10-23 evening, laptop; `rerun/cm_study/`)

**Where the common mode is removed.** Every June production row was taken RAW: `run_config` has `zero_suppress`,
`pedestal_subtraction` and `common_noise_subtraction` all False (only the pre-June ArIso/ZS test runs had on-FEU
CM). The decoder does no baseline work (DreamDecoder.cpp read through). So the CM is removed only in software, in two
places, both the plain per-sample median of each 64-channel block (= one DREAM chip = one connector): the hits
analyzer (`applyCommonNoiseSubtraction`, also used for the pedestal RMS) and `wft.io`. Nothing is baked into the data:
the CM can be redone in the analysis at no cost.

**What the CM is** (`cm_structure.py`, golden files, signal-free events):

| FEU | raw noise → after CM (ADC) | CM rms per chip | chip CM left after the FEU-wide CM | X–Y CM correlation |
|---|---|---|---|---|
| det7 X (06) / Y (08) | 59 → 8.3 / 53 → 9.0 | 50–65 (X chip 0: 5) | 9–20 | −0.46 |
| det6 X (03) / Y (04) | 136 → 8.0 / 142 → 8.7 | 132–146 | 12–20 | −0.89 |

- It changes sample to sample (within-event rms ≈ total), so it has to be estimated per sample.
- Most of it is FEU-wide, but each chip keeps 9–20 ADC of its own, more than the noise (8–9): quiet chips cannot
  stand in for a chip that holds a track.
- The X and Y FEUs of one detector are **anti-correlated**.
- Per-channel pick-up is uniform to ±5–15 % (slope p1–p99 0.9–1.15 apart from dead channels); a per-channel slope
  lowers the noise only 8.05 → 7.78 ADC. Not worth a model term.
- det7 X chip 0 carries almost no CM (5 against ~60 ADC), as if its strips were not connected to the detector. Open:
  check against the dead-strip masks.

**What the plain median does to a track** (`cm_inject.py`): real clusters (cleaned with a ±10-strip masked CM, zero
outside) injected into real signal-free events of the same file, 1000–1200 per plane, all five chambers, both views;
error = E(quiet + signal) − E(quiet), which isolates the signal-induced part. Median bias on the window-integrated
charge of the ±k neighbours:

| estimator | ±1, ±2 | ±3 | ±5 |
|---|---|---|---|
| plain median (production) | −0.2 … −2.5 % | −0.5 … −6 % | −1 … −25 % (narrow clusters worst) |
| masked, ±5 strips (`WFT_CM_MASK=5`) | ≤ 0.1 % | ≤ 0.3 % | ≤ 1 % |

The masked estimator also has the smaller random error (|ΔQ±3| p90 roughly halved). Mask half-widths 2–8 behave the
same; 5 is chosen. A fallback to the FEU-wide CM for a fully covered chip changes nothing measurable (too rare).
**Correction to C9:** the "10–25 % of a neighbour's tail" there compared two estimators on the same event (it
includes the masked estimator's own noise); isolated by injection, the plain-median bias is the table above: small
near the core, large in the far tail, which is where D_rc and the diffusion width are measured.

**The hits analyzer**: `--cns-mask M` added to `analyze_waveforms` (mm_strip_reconstruction, same rule as wft.io);
`--cns-mask 0` is bit-identical to the production hits (det7 golden file 000, FEU 06 and 08). With M = 5 the hit
count rises 18 % (X) / 24 % (Y), mostly 1–5 channels from a cluster (cluster edges the biased baseline had pushed
under threshold). Whether the re-hit adopts it is a decision (hits are seeding, efficiency and QA, not geometry).

## C13 · M3 chain re-audited; hits common mode decided on data (2026-10-23 night, `rerun/m3_audit/`)

**Judge** (`judge.py`): independent of M3's own χ². Every clean M3 ray (NClus ≥ 3 both views, 0 < χ² < 5, one per
event) is projected to the detector; the detector's largest-charge cluster per view (combined hits, hot channels
> 20 % occupancy dropped) is tied to it by an affine fit per view on the baseline rays with the plain-CM hits, then
frozen. Read inside the footprint: match = cluster within 5 mm in both views; residual width (1.4826 × MAD). Rays
a variant adds are scored separately. Golden files: det6/det7 6-26 long_run 000/005, det3 Saturday 000–003, det3
weekend 01H34 000/004, det4 6-24 000/003, det2/det3 6-22 longer_run 000/001.

**M3 provenance.** All 181 June M3 acquisitions have v2 rays (DataReader/tracking of 7-05, `config_ref_june2026`,
pedestal of their own subrun or night). Source changes since: b71ffc9 (8-25) adds output branches only; akallitss's
fork adds configs/CI/docs only. A clean rebuild reproduces the production rays exactly on all 12 golden files
(event order differs: the tracking is multi-threaded; compare keyed on evn).

**The algorithm, read again.** 61 channels → 1037 strips by genetic multiplexing per plane; channels > 4σ for > 3
samples; cluster = longest run of strips whose channels fired; charge-weighted centroid with shared channels split;
plain per-chip median CM; track = minimum-χ² combination over the 4 layers, a layer dropped only if no 4-layer
combination has χ²/n < 200 mm². Two candidate improvements were written (opt-in, off = bit-identical, verified on
the 12 files) and judged:

|---|---|---|---|
| production | 19 691 | 91.3 %, σ 0.80/0.75 mm | — |
| outlier rescue (`M3_OUTLIER_CHI2=5`: a failing 4-layer fit replaced by its best 3-layer subset) | +27 % | 84.1 % | match 58–65 %, σ 1.1 mm: mostly worse or fake tracks; **rejected** |
| masked CM in M3 (`M3_CM_MASK=0/1`) | ±2 % swapped | 91.2–91.3 % | no change in match or σ on any chamber (a track lights 3–6 of 64 channels); **not needed** |

Same picture on det2, det4, det6, det7 and the det3 weekend. **The production M3 rays stand; no re-tracking.**

|---|---|---|
| det6 | 90.0 % | 78.1 % |

## C18 · Why the v estimators disagree: three different quantities (2026-10-24, laptop + condor 4544416, `rerun/vladder/`)

**What each one measures.**
- **Timing v** (`cloud_basics/vdrift_consistency.py`) = G / T: G from the half-height extent of inclined tracks'
  charge against z = (x − x_mesh)/tan_ref (no timing at all), T the head-on stack's drift duration. Kernel-free.
- **Reconstruction (ladder) v** = d w / d tan_ref. The per-event fit never uses v: it fits (p0, w, t0) and only
  converts tan = (w − w0)/(kw v) at the end. So v_bundle × kw is an angle scale, and the reco's own v is the slope
  of the fitted transverse speed against the M3 angle (M3's slope scale enters G and the ladder identically).
- **Calibration-fit v** (recal.py, v free) = the w = v · tan_ref tie inside a ref-pinned objective. Its χ² is flat
  along v (C17), so its minimum is set by how the M3 reference holds the line at the mesh (pinned / ±1 / ±2 mm / dz).
  **It is not a measurement**; that is the whole 15–25 % arm scatter.

## C19 · The starting-angle problem, and what the v disagreement on det2/4/6/7 is (2026-10-24 afternoon, laptop + condor 4544620, `rerun/seedfit/`)

**Landscape** (`seedfit` maps of χ² over (w, p0) for failing events): along w at the right p0 the χ² has ONE narrow well
(3–5 µm/ns wide); the trouble is p0, the mesh END of the track, up to w · (half the column) ≈ 5 mm from the charge.
Started at w = 0 on the brightest strip, a fit sits in a diagonal (w, p0) valley next to a broad w ≈ 0 shelf. Two
more defects: with the RC kernel χ² is a staircase in t0 (`build_matrix_rc` snaps t0 to the 5 ns tensor grid; the
delay kernel interpolates), so Nelder–Mead stalls along t0; and the t0 prior (±5 ns, adds ((t0 − t0p)/5)²) is
invisible next to χ² of 10⁴–10⁶, so it never selects the 60-ns basin it was designed for. Most residual
"χ² above best" cases are t0 basins at the same w (angle unaffected).

**Fitters compared** (400 held-out events per chamber, RC it0 timeD bundles; "wrong w" = |w − w of the lowest χ²
found by any fitter| > 1 µm/ns; X view, det3 / det2 / det4 / det6 / det7):

**The pivot start** (`wft.reco.PIVOT_START`, `WFT_PIVOT_START=1`, opt-in, default path untouched; tests
`wft/tests/test_pivot_start.py`, suite 75 passed): a straight track passes through its own charge centroid
(x_c, t_c) whatever its slope, and both are model-free — x_c the charge-weighted strip position, t_c the
charge-weighted sample time minus the impulse response's own time centroid (convolution adds means; no
deconvolution needed, the deconvolved version is identical in performance and slower). Scan w (±0.032 mm/ns,
0.002 steps) with p0(w) = x_c − w (t_c − t0), refine the two best wells with fit_plane_raw. Same cost as
_global_start, fewest wrong-basin fits of the cheap starts on every chamber, resolution equal or better except det3 X
(+0.02°). Two-sided remains the most thorough (lowest χ²) at 3–5× the cost, with no resolution gain.
`heldout_eval.py --start {reco (default), pivot, bare}`: evaluations now use the pass's own fitter.

**det3 is consistent.** Pivot, all 1300 held-out events: ladder 36.01 ± 0.13 (X), 35.75 ± 0.15 (Y) against timing
35.8 ± 0.6. The earlier Y 35.1 was the 400-event subsample.
