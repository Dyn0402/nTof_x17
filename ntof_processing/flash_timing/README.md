# γ-flash timing calibration — n_TOF EAR2 X17, 2026 campaign

**Measured 2026-07-28 from the seven runs in the campaign that were taken with
the SiPM-wall divert disabled. Intended as the definitive flash-time
calibration.**

Tables and figures here are regenerated by `scripts/make_tables.py`,
`scripts/make_figures.py` and `scripts/make_figures_v2.py`; the machine-readable
calibration is `data/flash_timing_calibration.json`.

**Written up as documents too:** `latex/flash_timing_calibration.pdf` (8-page
report) and `latex/flash_timing_slides.pdf` (16 slides). Rebuild both with
`make -C latex`.

---

## 0. The result, and how to use it

```
t_flash_at_detector(bunch)  =  tof_PKUP(bunch)  +  C[detector]
```

`tof_PKUP` is the `tof` of that bunch's PKUP hit (equivalently its `tflash` —
they agree). **`C ≈ −1719 ns` for all 32 wall channels**; per-channel values are
in Table 1 and in the JSON.

```python
import json, numpy as np
cal = json.load(open('flash_timing_calibration.json'))['constants']
C   = cal['WALA']['channels']['3']['C_2026_07_16']      # -1721.79 ns
t_since_flash = hit_tof - (pkup_tof[hit_bunch] + C)
```

**Do not use the PSA's stored `tflash` for the walls, the plastics or the
liquids.** In gate-on runs the wall flash finder is bistable *within a single
run* — it tags the divert-gate transient in some bunches and the clamped flash
leak in others, so no per-run offset can repair it. PKUP's finder never fails
(§3.2), which is why the whole calibration hangs off it.

Accuracy you can expect:

| effect | size |
|---|---|
| run-to-run reproducibility, within an epoch | **0.5 ns** |
| transport from the 07-16 epoch to the end of the campaign (LIQ-verified) | **1.2 ns** |
| 07-11 vs 07-16 epoch difference (real hardware change) | 3.9 ns |
| beam-intensity walk, parasitic → dedicated | 5.0 ns |
| single-bunch spread of one channel | 3.5 ns |
| single-bunch spread of the 32-channel average | 2.5 ns |

## 1. Why this needed special runs

In normal running the SiPM wall signal is diverted around the γ-flash by a ~1 µs
blanking gate (N1081B module 6, section C, outputs 1–2 → "SiPM enable"). The
walls therefore never record the flash: the PSA locks either onto the gate
transient — 1190 ns before the flash in the July-11 configuration, 375 ns after
the gate delay was changed 200 → 1000 ns on 2026-07-22 — or onto a clamped leak
at the true flash time. That bistability is the origin of the ~350 ns
cross-detector offsets in `../flash_calibration.json`, which this work replaces.

Seven runs escaped the gate; they are the only direct view of the true flash
arrival in the walls.

## 3. Measurements

Method: for every (bunch, channel) take the largest-amplitude hit within ±300 ns
of the bunch's flash anchor, and subtract that bunch's PKUP pulse time. Quote
the mean over bunches after a ±100 ns core cut that removes PSA mis-tags. `tof`
is quantised to 1 ns, so the mean over ~3000 bunches carries a statistical error
of 0.06 ns — every number below is systematics-limited, not statistics-limited.

### 3.1 Per-channel constants

Full table: Table 1 below / `data/per_channel_flash_timing.csv`. Summary:

| wall | C, all 7 runs | C, 07-11 | C, **07-16 (recommended)** | channel spread | per-bunch σ | flash amp | risetime |
|---|---|---|---|---|---|---|---|
| WALA | −1717.5 | −1716.7 | **−1719.5** | 5.2 ns (range 14.0) | 3.2 | 28 613 | 16.3 ns |
| WALB | −1719.3 | −1719.1 | **−1719.7** | 3.2 ns (range 10.8) | 3.1 | 28 515 | 14.5 ns |
| WALC | −1715.5 | −1714.0 | **−1719.2** | 1.9 ns (range 5.3) | 3.6 | 28 295 | 16.9 ns |
| WALD | −1714.1 | −1712.2 | **−1719.0** | 3.9 ns (range 12.1) | 3.4 | 28 246 | 16.9 ns |

Note what happened between the epochs: on 07-11 the four walls sat 7 ns apart;
by 07-16 they agree to **0.7 ns**. The shift is per-channel (WALB −0.6 ns,
WALD −6.9 ns), i.e. a front-end/bias change, not a cable change — consistent
with the wall threshold/HV equalisation of 07-15/16. The equalised state is the
one that held for the rest of the campaign, which is the second reason to
prefer the 07-16 constants.

`satuflag` is 0 on every flash hit: 28 500 of a 65 536 range with a −949 mV
baseline offset is not ADC clipping (the *front end* saturates — see §5).

### 3.2 The reference: PKUP

| | |
|---|---|
| per-bunch spread of `tof_PKUP` | **0.83 ns** (dedicated), 1.42 ns (parasitic) |
| bunches with a usable pickup pulse | **98.4 %** (all 1.6 % failures are parasitic) |
| walk with intensity | **−0.45 ns** for a ×2 in protons |
| amplitude linearity | 14 421 → 28 345 ADC for ×2 protons (**ratio 1.97**) |

PKUP is a near-ideal reference: unsaturated, linear in beam intensity, stable at
the 1 ns level, and never mis-tagged.

### 3.3 Timing resolution (`figures/02`, `figures/04`)

Decomposing the 32-channel matrix, bunch by bunch (`data/resolution_decomposition.json`):

| component | 07-11 runs | 07-16 runs |
|---|---|---|
| single channel vs PKUP | 3.9 ns | 2.7 ns |
| common to all 32 channels | 2.7 ns | 2.0 ns |
| independent per channel | 2.8 ns | 1.9 ns |
| 32-channel average vs PKUP | 2.7 ns | 2.0 ns |

The independent part averages away over 32 channels; the common part does not.
Since PKUP itself contributes only ~1 ns, most of that common 2.5 ns is a real
bunch-to-bunch variation of the flash arrival (or of the digitiser window start)
— it is a floor on how well any single bunch's flash time can be known, and it
is the same for every wall.

### 3.4 Beam-intensity dependence (`figures/02`, `06`, `07`)

| tree | parasitic 4.1e12 | dedicated 8.5e12 | walk |
|---|---|---|---|
| WALA | −1714.6 | −1719.4 | **−4.8 ns** |
| WALB | −1716.6 | −1721.1 | **−4.5 ns** |
| WALC | −1712.5 | −1717.6 | **−5.1 ns** |
| WALD | −1711.2 | −1716.2 | **−5.0 ns** |

**Is the flash actually arriving earlier, or is it our timing metric?** It is the
metric — three independent arguments (`figures/06`, `07`):

1. **The shift is detector-dependent**: 0 (PKUP), −5.0 (walls), −3…−6 (plastics),
   **−16 ns (SILI)**. The same flash is seen by all of them, so a genuine change
   in its arrival time would move them all equally.
2. **PKUP does not move.** It timestamps the very protons that make the flash,
   its amplitude doubles between the classes (ratio 1.97), and its time moves
   −0.45 ns. The flash cannot precede its own protons.
3. **Classical amplitude walk is excluded quantitatively.** Measure the
   amplitude→time slope *within* one intensity class and extrapolate it to the
   observed change of median amplitude *between* classes: it predicts **+0.3 ns**
   for the walls (wrong sign) and <0.4 ns for everything else, against −5…−16 ns
   observed.

*(the panel titles inside each PNG are numbered 1–15 across the whole set; the
file numbers 01–11 are what is referenced here.)*

The mechanism is front-end saturation: a bigger flash cannot make a taller pulse,
so it reaches the clipping level *earlier* and stays there longer — wall risetime
20.5 → 15.4 ns (−25 %) and FWHM ~700 → ~2000 ns; SILI risetime 98 → 56 ns, with
the PSA saturation flag set on 78 % of its flash hits (the most saturated
detector, and the largest shift). Any edge-based estimator therefore fires early.

*Practical consequence:* carry it in the calibration (use the constant matching
the pulse type, or apply −5 ns per class; intensity is in `PulseIntensity`) — but
do not interpret it as physics.

### 3.5 Stability within a run (`figures/03`)

Pooling all 32 channels in 40 bins across a full 3-hour run: bin-to-bin spread
0.25–0.39 ns, maximum excursion 1.4 ns, first-vs-last ≤0.7 ns. No drift.

### 3.6 Does it transport, and does anything drift? (`figures/05`, `11`)

This is the load-bearing question, because all seven divert-off runs are from
07-10/16 while the physics runs continue to 07-28 — and the walls cannot be
measured directly in between.

The liquid scintillators answer it. **LIQ and PSS are never gated, so they see
the true flash in every run.** Measuring their flash time against PKUP run by
run (`data/plastic_liq_flash_by_run.csv`, 81 runs):

| tree | mean C | std over runs | runs | span |
|---|---|---|---|---|
| LIQA | −1708.22 | **0.73 ns** | 39 | 224400–224584 |
| LIQB | −1710.30 | **0.73 ns** | 36 | 224458–224584 |
| LIQC | −1695.56 | **0.77 ns** | 36 | 224458–224584 |
| LIQD | −1701.56 | **1.48 ns** | 39 | 224400–224584 |

The time base is stable to ~1 ns from 2026-07-13 to 07-28, on four independent
detectors. And LIQ exists in the 07-16 divert-off runs, which tie the wall
measurement into that chain: LIQ in 224464/224466 sits **+0.9 to +1.2 ns** from
its late-campaign mean. So the 07-16 wall constants carry to the end of the
campaign with ~1.2 ns confidence.

**Is there any variation in time?** Yes, but small and *common*. The four LIQ
cells move together — the within-run spread of their deviations from the
campaign median is **0.22 ns** and the LIQA–LIQC correlation across runs is
**+0.92** — so what the time series shows is a wander of the shared time base,
not detector noise. Its size:

| | |
|---|---|
| common-mode wander, r.m.s. over the campaign | **0.68 ns** |
| largest single-run excursion | **−2.23 ns** (run 224531, all four cells) |
| runs deviating > 1.5 ns | 1 of 39 |

That 0.68 ns is the systematic floor of the PKUP-referenced time base, and it is
smaller than every other term in the budget.

**Independent check in gate-on runs.** Where the gate is on, the walls still
emit a clamped leak. Its position, measured against the calibration in runs
224362 (07-11 era) and 224572 (07-26, i.e. 15 days after the nearest calibration
run and after the gate delay change), lands **within 6.2 ns on average, 9.2 ns
worst-case**, on all 32 channels in both epochs. The gate transient meanwhile
sits at −1190 ns (224362) and −375 ns (224572) relative to the true flash —
exactly the +800 ns predicted by the SEC_C delay change of 07-22.

### 3.7 Plastics — measured, quantified, and not usable (`figures/08`–`10`)

| channel | C | per-bunch σ | bunches with a flash hit |
|---|---|---|---|
| PSSA ch1 / ch2 | −1625.7 / −1644.5 | 25.0 / 16.2 | 69 % / 65 % |
| PSSB ch1 / ch2 | −1655.4 / *−1555.0* | 18.2 / *73.3* | 70 % / 62 % |
| PSSC ch1 / ch2 | −1653.7 / −1648.6 | 24.6 / 25.8 | 62 % / 70 % |
| PSSD ch1 / ch2 | −1652.4 / −1640.2 | 17.5 / 17.8 | 72 % / 71 % |

Three distinct failure modes, quantified in `data/plastic_pathology.csv` and
`figures/08`–`10`. Per detector family and epoch (`found` = fraction of bunches with
a large hit within 60 ns of the modal flash position; `n_hit` = hits per bunch in
the ±1 µs flash window):

| epoch | family | found | σ [ns] | amplitude | PSA sat. flag | FWHM [ns] | n_hit/bunch |
|---|---|---|---|---|---|---|---|
| 2026-07-11 | WAL | 100 % | 4.1 | 28 521 | 0 % | 1527 | 12.4 |
| 2026-07-11 | PSS | **67 %** | **19.1** | 23 193 | 0 % | 11 | 38.2 |
| 2026-07-16 | WAL | 100 % | 2.3 | 28 560 | 0 % | 2602 | 12.5 |
| 2026-07-16 | PSS | 64 % | 5.8 | 34 571 | 0 % | 43 | 26.0 |
| 2026-07-16 | LIQ | **100 %** | 4.1 | **63 931** | **80 %** | 103 | 43.6 |
| 2026-07-26 (post-FIFO) | WAL | 100 % | 8.3 | 19 650 | 6 % | 57 | 11.7 |
| 2026-07-26 (post-FIFO) | PSS | **42 %** | 2.5 | **55 114** | 27 % | 76 | 24.3 |
| 2026-07-26 (post-FIFO) | LIQ | **100 %** | 4.5 | **63 921** | **79 %** | 102 | 44.1 |

("found" = the PSA put *any* hit within ±60 ns of the flash position in that
bunch; σ is for the largest-amplitude hit there.)

1. **Yield.** A hit at the flash time exists in only 64–67 % of bunches, falling
   to **42 %** after the FIFO fan-in (07-17), when the plastic flash pulse starts
   railing the digitiser (median 55 000, up to 63 600 of a 65 536 range). In the
   bunches where it is missing the PSA reconstructs **no hit at all** before
   ~−1600 ns — checked against my own extraction window, which covered the flash
   region in 100 % of those bunches, so this is a genuine reconstruction failure.
2. **Amplitude-dependent bias and spread.** When a hit is found, its time
   depends on its amplitude: in 224357 the median moves **17 ns** between the
   lowest and highest amplitude bins with σ = 7–15 ns. Post-FIFO the precision is
   much better (σ = 2.4–3.4 ns, bias 4 ns) but the yield collapses — the two
   regimes trade against each other.
3. **Instability in time.** The constant moves by tens of ns across the campaign
   (σ_run 17–31 ns) as the plastic HV was equalised (07-16) and the FIFO went in
   (07-17). *PSSB ch2* is defective throughout (amp 9 778 vs ~30 000) and is
   excluded from the tree constant.

**And it is not simply "saturation breaks the PSA".** The liquid scintillators
are the control: they sit on the same digitiser and the same PSA, and their flash
hits are **more** saturated than the plastics' (saturation flag on **79–80 %**
against 27 %, amplitude 63 900 against 55 100) — yet the PSA finds their flash in
**100 %** of bunches at σ = 4.1–4.5 ns, with the highest hit multiplicity of all
(44/bunch). The walls are likewise 100 % efficient at σ = 2.3–8.3 ns.

So the plastic drop-out is specific to the plastic channel — its PSA
configuration and/or its pulse shape (the PSS flash pulse is wide and enormous in
area, FWHM 43–76 ns against 6 ns for a LIQ pulse of comparable height picked at
the same instant) — and **not** a generic consequence of a railed pulse.
**That makes it plausibly fixable in the `UserInput`**, which is directly
relevant to the reprocessing effort in `../HANDOFF_2026-07-28_ntof_processing.md`.

**Take plastic constants per run from `data/plastic_liq_flash_by_run.csv`, never
from a single epoch.**

## 4. What to do in practice

1. **Walls** — use `C_2026_07_16` per channel for runs ≥ 224400; `C_2026_07_11`
   for earlier ones. Add −5 ns if you are on dedicated pulses and calibrated on
   parasitic (or just use the per-intensity numbers in the JSON).
2. **Liquids** — use the per-run value, or the campaign mean; they agree to
   ~1 ns.
3. **Plastics** — per-run value only.
4. **Never** use the stored `tflash` of WAL/PSS/LIQ. Use PKUP.
5. If a run has no usable PKUP pulse for a bunch (1.6 %, all parasitic), drop
   the bunch rather than falling back on `tflash`.

## 5. Known limitations

- **Amplitude is useless here.** The undiverted flash saturates the wall front
  end: amplitude is flat when the protons double (ratio 0.99 on all 32
  channels). These runs give timing only; for energy scale use the Y-88 runs
  224476–224479.
- **The 07-11 → 07-16 shift (3.9 ns) is real** and per-channel. It means the
  wall front-end timing *can* move; nothing guarantees it did not move again
  between 07-16 and 07-28, beyond the LIQ evidence (§3.6) that the shared time
  base did not.
- **Runs before 224345 are unverified** (no wall trees in the official
  processing).
- **Raw data for all seven runs has aged off EOS disk.** Everything here comes
  from the official processed files; a waveform-level study (e.g. of the
  saturation shape) needs a `StageRuns.sh` tape stage.
