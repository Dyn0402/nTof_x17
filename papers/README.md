## Layout of a paper

    main.tex            class, packages, \input of the sections (one file per section, so edits rarely collide)
    sections/NN_*.tex   the text
    figures.toml        the figure manifest: one [fig.<id>] per figure
    figures/<id>.pdf|png  generated by ../make_figures.py -- don't edit by hand
    drafting.sty        outline macros (identical in both papers)
    refs.bib

## Drafting macros

| macro | renders as | use |
|---|---|---|
| `\sectionstate{ready}{backed by …}` | coloured box | PAPER_PLAN state and where the result lives |
| `\intent{…}` | grey italic | what the section must establish; delete when the prose exists |
| `\tbw{…}` | dark grey `[To write: …]` | an outline of prose still to write. Drafted prose is plain text: once a paragraph is written, drop the `\tbw` (2026-11-04: prose wrapped in it rendered grey and made the draft hard to read) |
| `\askStephan{…}`, `\askDylan{…}` | inline orange / cyan box | questions for a person; also listed on page 1 |
| `\analysis{D3}{…}` | inline red box | analysis still to do, with its work-list id |
| `\requote{1.15°}` | purple with RQ | a number that must be re-derived before it is quoted |

`\draftnotesfalse` in `main.tex` hides all of them for a clean read.

## Figures: how to swap one

Every figure is `\includegraphics{<id>}` with no extension, so the `.tex` never changes. The file comes from
`figures.toml`:

    state = "current"      copy `source` as it is
    state = "superseded"   show `source` faded under "SUPERSEDED: DO NOT QUOTE" (hits-based angles, positions, depths)
    state = "placeholder"  grey box with the title, a note and the producer command

To replace one: point `source` at the new file, set `state = "current"`, then

    .venv/bin/python papers/make_figures.py paper1                 # or paper2, or all
    .venv/bin/python papers/make_figures.py paper1 --only gas_vE   # one figure
    .venv/bin/python papers/make_figures.py paper1 --run           # run each `producer` first
    .venv/bin/python papers/make_figures.py all --list             # status table only

Floats are `[tbp]` and `placeins` keeps them inside their section (`main.tex`); use `[tbp]`, not `[t]` or `[h]`, for new ones, or they pile up at the end of the document.

A missing source falls back to a placeholder, so the paper always compiles. The reconstruction-basis rule
applies: no position, angle or depth from `combined_hits` times may be `current`.

## Overleaf (tracked changes for Stephan)

Each paper is its own Overleaf project, kept in step with `papers/<paper>/` by `git subtree`
(`overleaf.sh`). The repo stays the home of the figures and scripts. Overleaf is where people edit and review.

**Link a paper (once):**
1. In Overleaf, create a **Blank Project** (e.g. "MX17 Paper I"). Then go to Menu → Integrations → Git and copy
   the URL (`https://git.overleaf.com/<id>`).
2. Generate a token: Account Settings → Git integration. When git asks, the username is `git` and the password
   is the token. To store it once: `git config --global credential.https://git.overleaf.com.helper store`
   (plain text in `~/.git-credentials`) or libsecret.
3. `papers/overleaf.sh link paper1 https://git.overleaf.com/<id>`. This replaces the blank project's files with
   ours as a fast-forward and records the link in this repo. Commit any local changes first.
4. In Overleaf: Share → add Stephan as Editor. Turn **Track changes** on for everyone (Review → Track changes).
   In the project settings, choose pdfLaTeX, and choose `main.tex` as the main document.

**Day to day:**

    papers/overleaf.sh pull paper1   # bring Overleaf edits into the repo (commit your own work first)
    papers/overleaf.sh push paper1   # send repo commits (new figures, text) to Overleaf
    papers/overleaf.sh sync paper1   # both

It never forces. If Overleaf moved on, a push is refused: pull first. Then push to `origin main` as usual.

**"Maximum function recursion depth (1000) reached"** (seen on the laptop, 2026-10-23): git runs `git-subtree`
under dash, which caps recursion, and this repo's history is deep enough to hit it. Run the split under bash, then
push the split commit (still a plain fast-forward, never forced):

    D=$(mktemp -d); for f in /usr/lib/git-core/*; do ln -s "$f" $D/; done
    rm $D/git-subtree; sed '1s|.*|#!/bin/bash|' /usr/lib/git-core/git-subtree > $D/git-subtree; chmod +x $D/git-subtree
    split=$(GIT_EXEC_PATH=$D git subtree split -q --prefix=papers/paper1)
    git fetch overleaf-paper1 && git merge-base --is-ancestor overleaf-paper1/main $split && git push overleaf-paper1 $split:main

### Shared editing with Stephan: rules and protections (2026-11-06)

Claude edits the repo copy and Overleaf is a separate copy, so nothing Claude does appears as a tracked change,
and a push can reload a file under someone who has it open. `overleaf.sh` now guards this:

| command | what it does |
|---|---|
| `status <paper>` | read-only: Overleaf-only commits (who, when), any hold, the files a push would change |
| `pull <paper>` | tags HEAD `overleaf-backup/<paper>-<time>` first; on a conflict **aborts the merge**, leaves the repo clean and lists the files |
| `push <paper>` | fetches first; refuses if Overleaf is ahead, if a hold is set, or if Overleaf's last commit is under 30 min old (`--now` overrides); prints the files it changes |
| `hold <paper> "why"` / `release <paper>` | tracked flag `papers/.overleaf-hold-<paper>`: blocks every push, on every machine, while Stephan works |

Rules for Claude (also in the project `CLAUDE.md`):
1. `status`, then `pull`, before editing any paper text. Pull again right before a push.
2. Never use `--now`, never remove a hold, and never resolve a pull conflict, without Dylan saying so. Report it.
3. Don't edit a `sections/*.tex` that Overleaf changed since your last pull, unless Dylan asked for that section.
4. Push small and often (a section or a figure at a time), not one big push at the end of a session.
5. Figures are generated (`figures/*` from `make_figures.py`): if Stephan changed one in Overleaf, don't regenerate over it; ask.
6. Say in the report which files were pushed, so Stephan can look at them in Overleaf's history (they are not tracked changes).

Rules for Dylan and Stephan: Track changes on; accept or reject before a pull; Stephan says when he is in a
section, and Dylan runs `hold` for longer sessions. Overleaf history (Menu > History) shows every Claude push.

**Tracked changes are an Overleaf-only feature.** The git bridge carries the plain text, not the review
markup. So:
- Accept or reject Stephan's tracked changes in Overleaf before you pull.
- Don't push repo edits to a section that still has pending tracked changes or comments. Edit that section
  in Overleaf instead. New figures are always safe to push.

## The feedback note and drafting from it (Paper I, from 2026-11-04)

Dylan's hub note `~/.claude-hub/notes/dylan/archive/Paper I Feedback.md` mirrors the paper's outline: one heading per
section, subsection, figure and table, numbered as in the PDF (figures keyed by their file id, as in `figures.toml`).

    .venv/bin/python papers/note_outline.py paper1            # dry run
    .venv/bin/python papers/note_outline.py paper1 --write    # regenerate the headings (then commit ~/.claude-hub/notes)
    .venv/bin/python papers/note_outline.py paper1 --aux <build>/main.aux   # also check numbers against a build

Run it with `--write` after any change that moves, adds or renames a section or figure. Whatever is written under a
heading moves with it. Notes under a heading that no longer exists (a renamed section) go to a final "Unplaced"
section, never deleted, and the script names them.

**In the note, Claude acts only on unchecked `- [ ]` items** (Dylan, 2026-11-06). Everything else (plain text,
drafts, checked `- [x]` items) is left alone until Dylan puts a `- [ ]` on it, e.g. `- [ ] translate 2.1`, so he can
draft without it being picked up early. Don't translate, act on or "tidy" a draft just because it is there.
`- [ ]` items are for Claude to do. When one is done, check it off (`- [x]`) and add
`  > 💬 claude · <date>: …` under it with the details. An unchecked item that already has a 💬 was reopened by Dylan:
read the line he added and do it again.
Plain text under a section or subsection heading is Dylan's draft, written however it comes.
Inside a draft, `[…]` brackets are Dylan's notes to Claude (questions, "check this", "get numbers from X"), never
paper text: act on them while translating, and answer any that stay open in an `\askDylan{…}` or the 💬 line.

**Translating a draft into paper text** (when a `- [ ]` item asks for a section):
1. `overleaf.sh pull paper1` first; don't touch a section with pending tracked changes in Overleaf.
2. Write the section in `sections/*.tex` from the draft: Dylan's content, order and claims, in paper prose. Add no
   claims of our own. Every number is checked against its source (the result file named in `\sectionstate`, or
   `rerun/PAPER1_NUMBERS_*.md`). If the draft and a source disagree, or the draft is unclear, use an `\askDylan{…}`
   rather than guessing. Existing text the draft replaces is replaced; existing text it doesn't cover stays.
3. Build, push to `origin main` and to Overleaf, then add a 💬 under the draft: where it went (file, section number)
   and anything changed or questioned. Leave the draft in the note; Dylan deletes it when he's happy.
