## Layout of a paper

    main.tex            class, packages, \input of the sections (one file per section, so edits rarely collide)
    sections/NN_*.tex   the text
    figures.toml        the figure manifest: one [fig.<id>] per figure
    figures/<id>.pdf|png  generated by ../make_figures.py -- don't edit by hand
    drafting.sty        outline macros (identical in both papers)
    refs.bib

## Drafting macros

| macro | renders as | use |
|---|---|---|
| `\sectionstate{ready}{backed by …}` | coloured box | PAPER_PLAN state and where the result lives |
| `\intent{…}` | grey italic | what the section must establish; delete when the prose exists |
| `\tbw{…}` | grey `[…]` | placeholder prose ("to be written") |
| `\askStephan{…}`, `\askDylan{…}` | inline orange / cyan box | questions for a person; also listed on page 1 |
| `\analysis{D3}{…}` | red margin note | analysis still to do, with its work-list id |
| `\requote{1.15°}` | purple with RQ | a number that must be re-derived before it is quoted |

`\draftnotesfalse` in `main.tex` hides all of them for a clean read.

## Figures: how to swap one

Every figure is `\includegraphics{<id>}` with no extension, so the `.tex` never changes. The file comes from
`figures.toml`:

    state = "current"      copy `source` as it is
    state = "superseded"   show `source` faded under "SUPERSEDED: DO NOT QUOTE" (hits-based angles, positions, depths)
    state = "placeholder"  grey box with the title, a note and the producer command

To replace one: point `source` at the new file, set `state = "current"`, then

    .venv/bin/python papers/make_figures.py paper1                 # or paper2, or all
    .venv/bin/python papers/make_figures.py paper1 --only gas_vE   # one figure
    .venv/bin/python papers/make_figures.py paper1 --run           # run each `producer` first
    .venv/bin/python papers/make_figures.py all --list             # status table only

A missing source falls back to a placeholder, so the paper always compiles. The reconstruction-basis rule
applies: no position, angle or depth from `combined_hits` times may be `current`.

## Overleaf (tracked changes for Stephan)

Each paper is its own Overleaf project, kept in step with `papers/<paper>/` by `git subtree`
(`overleaf.sh`). The repo stays the home of the figures and scripts. Overleaf is where people edit and review.

**Link a paper (once):**
1. In Overleaf, create a **Blank Project** (e.g. "MX17 Paper I"). Then go to Menu → Integrations → Git and copy
   the URL (`https://git.overleaf.com/<id>`).
2. Generate a token: Account Settings → Git integration. When git asks, the username is `git` and the password
   is the token. To store it once: `git config --global credential.https://git.overleaf.com.helper store`
   (plain text in `~/.git-credentials`) or libsecret.
3. `papers/overleaf.sh link paper1 https://git.overleaf.com/<id>`. This replaces the blank project's files with
   ours as a fast-forward and records the link in this repo. Commit any local changes first.
4. In Overleaf: Share → add Stephan as Editor. Turn **Track changes** on for everyone (Review → Track changes).
   In the project settings, choose pdfLaTeX, and choose `main.tex` as the main document.

**Day to day:**

    papers/overleaf.sh pull paper1   # bring Overleaf edits into the repo (commit your own work first)
    papers/overleaf.sh push paper1   # send repo commits (new figures, text) to Overleaf
    papers/overleaf.sh sync paper1   # both

It never forces. If Overleaf moved on, a push is refused: pull first. Then push to `origin main` as usual.

**Tracked changes are an Overleaf-only feature.** The git bridge carries the plain text, not the review
markup. So:
- Accept or reject Stephan's tracked changes in Overleaf before you pull.
- Don't push repo edits to a section that still has pending tracked changes or comments. Edit that section
  in Overleaf instead. New figures are always safe to push.
