# Session notes (added by hand after the run)

## 1. Baseline vintage — read the "was" column with care

The "was" values come from whatever was on disk at 01:10 on 7-25, snapshotted
before anything was overwritten. Those files are NOT all the same vintage
(`rerun_baseline_vintage.json`):

| key | baseline files | comparable? |
|---|---|---|
| sat_det3 | 7-17 / 7-18 | yes |
| g_det3_wknd | 6-29 / 7-06 | **NO** — predates the 7-13 M3 recipe change (chi2<1 + NClus>=4) |
| o22_long_det2, g_det4, g_det6_long, g_det7_long | bulk 7-14 | yes |

So `g_det3_wknd`'s sigma_theta 2.12 -> 2.65 is apples-to-oranges (different
reference recipe), not a measured degradation. Every other key is same-recipe.

## 2. The efficiency drop is NOT the spark threshold

Tested non-destructively on the two extremes by re-running 09 at several
`--spark=` values and restoring the default output afterwards:

| key | thr 50 | thr 100 | thr 200 | thr 400 |
|---|---|---|---|---|
| sat_det3 within5 | 84.1 | 84.6 | 84.8 | — |
| g_det6_long within5 | 42.8 | 44.0 | 44.3 | 44.5 |

Raising the cut does not restore efficiency; it just moves events from `spark`
into `reco_far`. Those events DO reconstruct — they land >5 mm from the M3 ray.
The loss is position accuracy, not event classification.

## 3. What the hits actually look like (det6, one combined file, 1.5 M hits)

- 12.2 % of events have **>400 strips** firing on a 512-channel FEU
  (strips/event p90 = 471)
- those >400-strip events: median significance **12.2**, median amplitude **191**
- clean (<=50-strip) events:  median significance **35.1**, median amplitude **298**
- 43 % of all hits sit below significance 10; 29 % below 8

Full-board events with *lower* amplitude than ordinary events is the wrong
signature for discharges — it fits residual coherent/common-mode activity
surviving CNS and then passing the matched-filter gate. This is the leading
explanation for the fleet-wide precision loss.

## 4. Fleet pattern

Precision degrades on **every** detector (median |r| +22 % to +118 %, core sigma
+31 % to +120 %). Efficiency only improves where crossings were genuinely being
missed: det4 was at 69.6 % has_any and gains 15 points of within-5mm; every
other detector was already >=95 % has_any and only pays the precision cost.
Severity tracks spark_frac, worst at the 700 V points (det7 65.5 %, det6 42.4 %).

**Hybrid sigma68 improved on 6 of 6 detectors** (det6 gt8: 9.94 -> 4.90 deg;
det7 lt5: 3.17 -> 2.48 deg). The information is in the new hits; the classical
centroid/time-fit estimators are the ones that cannot handle the extra strips.

Suggested next test (one parameter, NOT run — your call): re-run 08/09 with a
significance floor above the 5-sigma gate and see whether within-5mm recovers
while det4 keeps its gain.

## 5. sat_det3 sigma_theta anomaly — open

`sat_det3` sigma_theta is bit-identical to the pre-rerun value
(2.417884172795585, n_events 6306 both times) while efficiency and time-res from
the same cache clearly moved. Ruled out:
- stale file — recomputing the angle correlation from the current cache in a
  scratch dir reproduces the on-disk JSON field for field
- stale cache — `cache/event_results_veto50.pkl` rebuilt 01:18, and 42's
  dualplane count changed 28404 -> 26230
- old-generation hits — all combined files carry `significance`, mtime 7-24 18:0x

Every other detector's sigma_theta moved (+9 % to +30 %). Unexplained.
