# run_145 re-reconstructed on the corrected sharing kernel

Record of the redo called for by `HANDOFF_RUN145_R06_2026-08-19.md`. Three of
the four arms were seeded from a bench bundle whose sharing ladder was inverted
(c₂ > c₁, which cannot happen — the ±2 strip is reached only through the ±1);
they now run on `calib_bundle_r06`.

**Scope.** run_145, sub-runs `stat090_0000` (7 file tags) and `stat090_0001`
(8), all four arms. Arm C is on `calib_bundle_lp` throughout — det6 was never
inverted, so C is **not** a correction; it is re-run only so that all four arms
sit on one code generation and one set of local tables.

---

## 1 · Two defects, not one

The handoff named one. The controlled comparison found a second.

**(a) The sharing kernel** — the one we set out to fix. A→det3 1.14, B→det2
1.53, D→det7 1.75, all now 0.60.

**(b) A bench clock, smuggled in with it.** `calib_bundle_r06` derives from
`calib_bundle_lp2_t0p`, so it ships `t0_abs` + `t0_prior_sigma = 5`. That is an
*absolute* arrival time in the readout window, calibrated on the bench against
**its** scintillator trigger and DAQ latency — a property of the trigger, not
of the chamber. run_145 is triggered by n_TOF. At σ = 5 ns it is a pin, not a
nudge.

Measured on tag 004, the same 3,267 events reconstructed both ways:

| | fitted t0, median (p16–p84) |
|---|---|
| no prior | 30 ns (−110 … +450) — free, and poorly determined on 20 samples |
| bench prior on | 236 ns (144 … 298) — sitting on the bench per-bin table (222–305) |

Whatever run_145's true t0 is, it is not the bench's stated to ±5 ns. Left in,
it would have been read as part of the kernel change. `wft_beam.make_bundle`
now drops both when seeding a beam bundle and records what it dropped
(`--keep-t0-prior` for when an in-situ t0 exists); the condor job re-asserts it
after seeding. Commit `11ce347`. **run_79's redo inherits this.**

## 2 · What the kernel alone does

tag 004 (3,267 events, 1/7 of sub-run 0000), arm A, one variable — same events,
same code, same v_drift (42.6), t0 prior off on both sides:

| | lp2 (superseded) | r06 (corrected) | |
|---|---|---|---|
| median tan θ ratio, X | — | — | **×1.0048** |
| median tan θ ratio, Y | — | — | **×1.0382** |
| `slope_reliable` fraction, X / Y | 0.535 / 0.587 | 0.535 / 0.593 | flat |
| k_track median | 1.206 | 1.215 | +0.8 % |
| v_insitu = 42.6/k | 35.33 | 35.06 µm/ns | −0.8 % |
| k_phys (coincident) | 1.248 | 1.251 | +0.2 % |
| r_core at focus | 10.77 | 10.55 mm | −2.0 % |
| frac in capsule | 0.0472 | 0.0475 | flat |
| confirmed / predictable | 513/1047 = 49.0 % | 503/1034 = 48.6 % | flat |

The kernel steepens Y about **eight times more than X**, which is the expected
shape — Y is the plane that shares more. But the imaging is a *fit*: `k`
absorbs nearly all of it, the focus comes out marginally tighter rather than
looser, and the external confirmation rate — the one handle that never touches
the fit's angle scale — does not move.

## 4 · How it was run

The laptop that owns this analysis measured ~310 kB/s aggregate to CERN on
2026-08-19 (parallel streams do not help; the link is the cap), ~140 kB/s by
scp from lxplus, and **23 kB/s by xrdcp** — so the 4.9 GB of decoded waveforms
was a ~60 h download. The reco went to the data instead:
`ntof_tracking/condor/`, one job per (arm, file tag), fetch to scratch at CERN,
same `wft_beam` driver, tar back the ~1 MB parquet; `merge_beam_tags.py`
stitches the tags into the one `events_prelim.parquet` per arm that the local
chain expects.

Guards, because each of these is silent once it reaches a worker: the package
refuses a bundle with c₂ > c₁ or one stamped `w0_kw_stale`; the job refuses a
seeded bundle that still carries a t0 prior; the merge refuses to stitch tags
reconstructed with different bundles, or to overwrite a table that is not
already parked.

**Trap, hit once:** `make_beam_package.py` failing on a dirty tree does not
stop a following `rsync && condor_submit` in the same shell — 45 jobs ran on
the previous `code.tar.gz`. Check that `CODE_COMMIT.txt` on lxplus matches HEAD
before believing a result.
